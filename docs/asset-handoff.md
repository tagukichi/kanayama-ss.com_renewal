# 素材の扱いと、プレビュー環境の方針

## 結論

| | 方針 |
|---|---|
| **メディア** | git に入れず、**現行サイトの URL を参照**する |
| **プレビュー** | **GitHub Pages**（GitHub Actions でデプロイ）。`robots.txt` と `noindex` で検索避け |
| **リポジトリ** | メディアを入れないので **public のままで可** |
| **組み方** | 静的HTML → WPテーマ変換 の現行方針を継続 |

公開URL: https://tagukichi.github.io/kanayama-ss.com_renewal/

`src/` を編集して push すると、GitHub Actions が `node build.mjs` を実行して自動デプロイします
（`.github/workflows/deploy-pages.yml`）。依存パッケージはありません。

> ⚠️ GitHub Pages は**認証をかけられません**（公開ページになります）。
> 掲載している写真はいずれも現行サイトで公開中のものなので新たな露出はありませんが、
> 検索に拾われないよう `robots.txt` と `<meta name="robots" content="noindex, nofollow">` を出力しています。
> 認証が必要になったら Xserver のテストドメインに Basic認証をかけて移す方が確実です。

## Pages と Xserver の使い分け

| | GitHub Pages | Xserver テストドメイン |
|---|---|---|
| 用途 | **今のデザイン確認** | **WPテーマ化後の動作確認** |
| PHP | 動かない | 動く |
| 認証 | かけられない | Basic認証をかけられる |
| 更新 | push で自動 | FTP/SSH で転送 |

デザインを固める段階は Pages で十分です。**テーマ化に入ったら PHP が必要になる**ので、
そのタイミングで Xserver に移します。

## なぜメディアを git に入れないか

現行サイトの画像は **すでに公開URLで配信されている**ため、URL参照なら新たな露出は発生しません。
一方 git にコミットすると、履歴・フォーク・クローンに残り、後から消せません。

副次的なメリット：

- リポジトリが重くならない（90点以上・数百MBになる可能性がある）
- メディアライブラリのエクスポート作業が不要
- **最終形に近い。** WPテーマでは画像はメディアライブラリから出力されるので、URL参照は本番構成そのものです

### 注意点

- **公開中のプレビューリンク（artifact）では外部画像が表示されません。**
  artifact は外部ホストへの通信を CSP で遮断しているためです。
  → 画像入りのプレビューは Xserver テストドメインで共有します
- 旧サイトを停止すると URL が切れます。**本番移行時に、テーマ内の参照を
  メディアライブラリ（`wp_get_attachment_image()` 等）に置き換えます**
- こちらの作業環境は外部通信が遮断されているため、**画像の中身を確認できません。**
  どの写真をどの枠に使うかは、下記のいずれかで指定をお願いします

## 画像の入れ方（かんたんな方）

**ページ名のフォルダに置いて push するだけ**で、そのページの空いている枠に自動で入ります。
`images.json` を編集する必要はありません。

```
src/assets/img/interview/   → 社員紹介ページの空き枠へ
src/assets/img/message/     → 代表メッセージページの空き枠へ
src/assets/img/works/       → 工事実績ページの空き枠へ
```

- フォルダ名は**ページのスラッグ**（URLの一部）と同じにしてください
- ファイル名は自由。**ファイル名の昇順**で枠に入ります。
  順番を決めたいときは `01_`, `02_` のように頭に番号を付けてください
- 枠より写真が多い場合、余った分は使われません（ビルド時にその旨が表示されます）
- push すれば GitHub Actions が自動でビルドして公開します

写真は `object-fit: cover` で切り取られるため、**縦・横・正方形のどれでも歪みません**
（中央基準でトリミングされます）。

## 画像の入れ方（枠を指定する方）

**`src/images.json` の `src` にURLを書いて `node build.mjs`** — これだけです。

```json
{
  "id": "index-01",
  "label": "メインビジュアル ／ 屋根上でのソーラーパネル施工",
  "size": "2000×1125px 以上",
  "src": "https://kanayama-ss.com/wp-content/uploads/2023/07/xxxx.jpg",
  "alt": "屋根の上でソーラーパネルを設置する職人"
}
```

- 全45枠のIDと用途は `docs/asset-slots.md` にあります
- **空欄の枠はプレースホルダーのまま**なので、1件ずつ埋めていけます
- `alt` は空欄なら「用途」から自動補完します。ページヘッダーなど見出しの背後に敷く写真は
  装飾扱いで `alt=""` になります
- ビルド時に `画像スロット: 12/45 件にURL設定済み` と進捗が出ます

### URL一覧の取り方

WP管理画面にログインした状態で以下を開くと、ファイル名・URL・寸法・altが一括で取れます。

```
https://kanayama-ss.com/wp-json/wp/v2/media?per_page=100&_fields=id,source_url,alt_text,media_details
```

※ 以前この REST API は外部から 403 でした。管理者権限で開けるかご確認ください。
開けない場合は、メディアライブラリの一覧から個別にURLをコピーしてください。

### 割り当てツール（推奨）

```
prototype/assign.html をブラウザで開く
```

現行サイトの写真を実際に見ながら、45枠へクリックで割り当てられます。

- 左の枠を選択 → 右の写真をクリックで割り当て（同じ写真をもう一度押すと解除）
- 各写真の**実寸法と縦横**を自動表示。枠の推奨向きと食い違うと ⚠ で警告します
- alt もその場で入力可能
- 入力内容はブラウザに自動保存されるので、途中でやめても大丈夫です
- 最後に「images.json を出力」→ その内容で `src/images.json` を置き換え → `node build.mjs`

使える写真の一覧は `src/media-pool.json` です。URLを足せばツールにも反映されます。

### どの写真をどの枠に使うか

**こちらの作業環境は外部通信が遮断されているため、画像の中身を見られません。**
割り当ての判断は次のいずれかでお願いします。

- **指定していただく** — `docs/asset-slots.md` の用途を見て、URLを `src/images.json` に記入
- **こちらで提案する** — メディアライブラリ一覧のスクリーンショットを `assets/brand/` に
  コミットしていただければ、**画像ファイルは読めるので中身を見て提案できます**
  ※ 顔写真が写るため、この方法を取る場合は **リポジトリを private に**してください

## 本番移行時にやること

URL参照は旧サイトが生きている間だけ有効です。テーマ化の最終段階で、
`src/images.json` の参照を WordPress のメディアライブラリ出力
（`wp_get_attachment_image()` / アイキャッチ / カスタムフィールド）に置き換えます。

## Xserver テストドメインの準備

確認させてください。

1. テストドメインに **WordPress はインストール済み**ですか？
2. **SSH は使えますか？**（Xserverのプランによります）
   - 使える → サーバー上で `git pull` する運用にできます
   - 使えない → FTP/SFTP でテーマフォルダを転送します
3. Basic認証をかけてよいですか？（検索エンジンへの露出と、写真の公開を防ぐため）

## 素材以外にいただきたいもの

| | 内容 |
|---|---|
| **ロゴ** | ベクター（`.ai` / `.svg` / `.eps`）。無ければ最大サイズのPNG → `assets/brand/` |
| **本文の原稿** | 現在は仮原稿です。WP管理画面の各固定ページからコピーしたテキストで可 |
| **会社情報** | 所在地・電話番号・設立・資本金・代表者名・許可番号（現在は伏せ字／`［支給待ち］`） |
| **プラグイン一覧** | 管理画面のスクリーンショットで可。特にフォーム・カスタム投稿タイプ・SEO系 |
| **works の構造** | カスタム投稿タイプ名、カスタムフィールド、カテゴリー |

詳細は `docs/request-list.md`、必要な画像の一覧は `docs/asset-slots.md` を参照してください。

## プロトタイプの簡易ゲートについて

`prototype/assets/gate.js` で、閲覧前にID・パスワードを求めています。

| | |
|---|---|
| ID / パスワード | `kanayama` / `kanayama` |
| 保持 | `localStorage`。同じブラウザなら一度入力すれば以後は素通し |
| 対象 | 全13ページ＋`preview.html`＋`assign.html` |

### ⚠️ これはアクセス制御ではありません

GitHub Pages は静的配信のため、**サーバー側で認証できません。** 判定はすべてブラウザ内で
完結するので、次の方法で回避できます。

- ページのソースを見れば判定ロジックが読める（平文は置いていませんが、突破は容易です）
- `…/interview.html` や `…/assets/img/interview/interview_01.jpg` を**直接開けば素通し**

見せたくない相手に確実に見せない必要がある場合は、**Xserver のテストドメインに置いて
`.htaccess` で Basic認証**をかけてください。そちらはサーバー側で処理されるため、
画像を含むすべてのファイルが保護されます。

```apache
# .htaccess
AuthType Basic
AuthName "Prototype"
AuthUserFile /home/<アカウント>/<ドメイン>/.htpasswd
Require valid-user
```

## FVスライダー

トップページのファーストビューはスライダーです。スライドの定義は `src/slides.json` にあります。

```json
{
  "interval": 6000,
  "slides": [
    { "id": "eight-fields", "src": "assets/img/slider/01_eight-fields.png",
      "alt": "エイトフィールズ株式会社 × 有限会社金山製作所",
      "overlay": false, "fit": "contain", "bg": "#F2F2F2" },
    { "id": "ladder", "src": "assets/img/slide_01_full.jpg",
      "tall": "assets/img/bg_01.jpg", "alt": "", "overlay": true, "pos": "8% 50%" }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `src` | 横長の画面で使う画像 |
| `tall` | 縦長の画面（タブレット縦・スマホ）で使う画像。省略時は `src` を使う |
| `alt` | 代替テキスト。装飾扱いのスライドは空文字 |
| `overlay` | `true` でキャッチコピーとボタンを重ねる。`false` は画像だけを見せる（バナー等） |
| `fit` | `cover`（既定）／`contain`。バナーのように全体を見せたい画像は `contain` |
| `bg` | `contain` のときの余白の色 |
| `pos` | 切り取り位置（`object-position`） |
| `interval` | 自動切り替えの間隔（ミリ秒） |

- **FVの高さは1枚目のバナー（1360×540＝約2.52:1）の比率に固定**しています。
  そのためバナーは上下に余白なく収まり、2枚目の写真も同じ高さになります。
  別の比率のバナーに差し替える場合は、`style.css` の `--slide-ratio` を合わせて変更してください
- インジケーターと実績の数字はスライダーの**下の帯**に置いています。
  バナーは端まで絵があるため、上に重ねると社名やロゴが隠れてしまうためです
- 画像は `src/assets/img/slider/` に置いてください
- **ファイルが未配置のスライドはプレースホルダー表示**になり、壊れ画像にはなりません
- 矢印と停止ボタンは表示しません。**現在位置のインジケーター**（クリックでその枚へ移動）のみ
- マウスが乗っている間・タブが非表示の間は自動送りを止めます
- 「動きを減らす」設定の環境では自動送りしません（1枚目を表示したまま）

### WordPress 化のときの対応

`slides.json` の配列を、そのまま管理画面から編集できる形に置き換えます。

| プロトタイプ | WordPress |
|---|---|
| `slides.json` の配列 | カスタム投稿タイプ「スライド」または ACF の繰り返しフィールド |
| `src` / `tall` | 画像フィールド（PC用／SP用） |
| `alt` | 画像の代替テキスト（メディアの設定を利用） |
| `overlay` | 真偽値フィールド「キャッチコピーを重ねる」 |
| 並び順 | 投稿の並び順、またはフィールドの並び |

スライダーのJavaScript（`assets/app.js`）は**DOMの構造だけに依存**しているため、
テンプレート側で同じ構造を出力すれば、そのまま使えます。
